# build-it-timer — core

WXT MV3 browser extension ("Build-it! Timer Focus"): a focus-session timer that grows a seeded 3D city (ASCII text fallback), blocks distracting domains during a session, and scores the session. Single TypeScript package — no separate deployable modules.

## Source map
- `entrypoints/` — `background.ts` (orchestrator), `blocked-overlay.content.tsx` (Shadow-DOM overlay), `popup/` (React UI).
- `store/` — Zustand store composed of `*.slice.ts` factories, `storage-adapter.ts` (persist adapter + self-write tracking), `sync-storage.ts` (`attachStoreSync`).
- `lib/` — pure domain logic (`url/`, `blocking/`, `timer/`, `city/`, `score/`, `messaging/`); only `lib/timer/alarm-adapter.ts` touches `browser.alarms`.
- `components/` — presentational React (`timer/`, `city/`, `blocklist/`, `score/`, `common/`).
- `utils/` — logger, duration formatting, hash, `Result`.
- `tests/` — unit · integration · e2e · helpers; unit tests mirror the source tree.
- `docs/` — `roadmap-en.md` (authoritative task cards), `changelog.md` (mandatory per-task record), `store-analysis.md`, `issue/`, `ui/ui-review-tasks.md` (UI.T* cards from the 2026-11 UI critique, a past review; logic parts delegate to roadmap CRs).
- `PRODUCT.md` (product truth, neutral/minimal voice) + `DESIGN.md` / `docs/ui/design.json` (visual system "The Phosphor Skyline": phosphor green `#7dfba0` sole UI accent, mono everywhere, glow only on active/earned/alarming text) — design authority for any UI work. The `impeccable` tool is no longer installed; the `/impeccable` commands in `docs/ui/ui-review-tasks.md` are history.
- `locales/en.yml` (default) + `locales/it.yml`.
- `CLAUDE.md` — binding design/testing rules (loaded every session). On demand: `docs/project-structure.md`, `docs/testing-matrix.md`; changelog procedure lives in the `changelog` skill (`.claude/skills/changelog/`).

## Invariants
- **Three worlds, typed messages only**: background / content script / popup never import each other's modules; they exchange `RuntimeMessage` variants (`lib/messaging/messages.types.ts`) via `sendMessage`/`onMessage` (`lib/messaging/bus.ts`).
- **Single writer = background.** The popup builds its store with `createAppStore({ readOnly: true })`; components call `request*` actions that send a `MutationMessage`, applied by `lib/messaging/apply-mutation.ts`. The popup converges through `attachStoreSync` (`storage.onChanged` → `persist.rehydrate()`; self-writes skipped via `SELF_WRITE`).
- **Pure core**: `lib/` functions receive clock/RNG/seed as parameters — no internal `Date.now()`/`Math.random()`. Collaborators are injected through slice factories (`StoreDependencies`) and ports (`AlarmProvider`, growth/rule appliers).
- **One city per session**, reset on the idle→running transition only; pause/resume keeps the built city.
- **Growth derives from cumulative `timer.focusedMs`** with the persisted wall-clock checkpoint `timer.lastAccountedAt` (not sampled ticks), so catch-up after popup close / worker restart is idempotent. Since CR6.T5b the background's accounting step advances progress only (`focusedMs`, `distractedMs`, `score.builtCharacters`) and never draws or grows layers; the malus (M4.T1 schedule, `lib/score/malus-escalation.ts`) is inside `calculateBuiltCharacters` over the cumulative `distractedMs` ticks, so the score, tiers, population and city floors lose the same amount (60 s on a blocked site in a 30-minute session costs 44 characters, not 20).
- **DNR**: blocklist → dynamic rules installed only while `status === 'running'`; there is a single blocklist (the allowlist was removed by CR1). The empty but enabled static ruleset (`public/rules/empty-rule-set.json`) must stay declared — Firefox ≤132 drops dynamic rules on restart without it.
- **City tab loading (#22)**: `useCityView` (`components/city/use-city-view.ts`) shows `LOADING CITY…`, runs `probeWebGl2()` after the first paint (`afterFirstPaint`), then loads `CityView3D` with a plain dynamic `import()` (no `lazy`/`Suspense`: React 19 throttles a Suspense reveal by about 300 ms). The probed canvas (made with `GL_ATTRIBUTES`) goes to the renderer (`probe` prop → `useCityRenderer` → `CityRendererOptions.canvas`): one WebGL context per view; an unused probe is released on unmount. First 3D frame 170–223 ms on the GPU (was 446–543); budget raised to 250 ms, #22 resolved.
- **Building brightness**: `WINDOW_BRIGHTNESS` 0.75 and `EDGE_BRIGHTNESS` 0.85 in `lib/city/plan/scene-data.ts` (applied to `scene.windowColors`/`edgeColors`), `BODY_DIM` 0.12 in `floor-slots.ts`; bloom in `post-processing.ts`. Neon signs are independent (`GLOW` 1.6 in `neon-signs.ts`).
- **Vertical neon signs (replaced the box signs)**: sign props carry `side` (`x`/`z`, camera-facing face) and `span` (floors); planned in `plan-props.ts` (quarter of ordinary buildings, ≥ 4-level ground section, ≤ 10), colored with another palette color than the building, drawn by `components/city/three/neon-signs.ts` as one mesh of flat strips (vertex colors ×1.6 for bloom), whole-sign buzz from `ambient-plan.ts` (`SignBuzz`, `signLevel`, 6–18 s). Text fallback has no signs.
- **Damaged top floor follows the current fall (I015)**: `selectVisibleFloors` keeps `advanceFall` state per plan (each drop of `builtCharacters` adds to the fall, any growth resets it), so only a falling city shows the red flickering partial floor; regrowth is construction. A view opened mid-session starts undamaged. `calculateLostCharacters` was removed.
- **The malus debt is by design (I013)**: `builtCharacters = max(0, focusChars − malus(distractionTicks))` over the session *totals*; a malus larger than the city is owed and paid back by later focus (the city looks frozen at 0 meanwhile), so the final count is order-independent. A forgiving step-by-step count was tried and rejected (it made early distraction cheaper). Documented in `city-3d.md` §5, `score-population.md` §1.1, README.
- **Distraction is accounted at the flip (I014)**: the tracker's `onBeforeDistractedChange` hook (bound to `growthTick.account` in the background) runs just before `isDistracted()` flips, so each stretch is booked to the tab state it was spent in. Without it, the 60 s heartbeat (popup closed) booked the whole minute to the state at that instant.
- **Distraction tracking**: `TabDistractionTracker` seeds open tabs once and otherwise follows `tabs.onUpdated`/`onRemoved`, so it must be `refresh()`ed when the timer enters `running` — the construction-time seed runs while the store is idle, and a tab already open on a blocked site never emits an update. Since CR6.T5b all `distractedMs` is charged (the pre-`proceed` time is no longer forgiven) and `MALUS_APPLIED { domain, charactersRemoved }` is only a report: `createMalusWiring({ store })` sends it when an accounting step that added distraction time lowers `builtCharacters`, once the overlay's "Yes" was chosen.
- **Persist**: key `timer-focus-store`, `version: 4` (CR6.T5a; v3 = CR4.T3), payload `{ timer, city: { sessionId }, blocklist: { blocklist, appliedPresetIds, userPresets }, score, sessionHistory, preferences: { sound } }` (`preferences` added by M5.T7 with no version bump: the merge sanitizes it and defaults it when absent); `partialize` excludes `ui`; keep the slice-aware `merge` so fields added later rehydrate to their default instead of `undefined`.
- **Both build targets are MV3**; Firefox gets a `background.scripts` event page instead of a service worker. Permissions are declared manually in `wxt.config.ts` (WXT does not infer them).
- **Blocklist (single list, CR1 complete)**: the allowlist was removed end-to-end — popup UI/locales (CR1.T1), mutation protocol (CR1.T2), persisted data migrated to `{ blocklist, customTags }` at version 2 (CR1.T3), enforcement (`buildDnrRules(blocklist)`, `isDomainBlocked({ blocklist })`, CR1.T4), production state model (CR1.T5a) and tests (CR1.T5b/T5c). `BlocklistState` is `{ blocklist, appliedPresetIds, userPresets }` since CR4 (was `{ blocklist, customTags }`); helpers/actions take no list name. **Never reintroduce a second list or a precedence rule.** The only runtime reader of the legacy field is `lib/blocking/legacy-blocklist.ts` (`migrateBlocklistState`); raw version-1 JSON fixtures remain only in the `legacy-blocklist`, `store-snapshot`, `blocked-overlay`, `store` and `dnr-rules` tests.
- **Blocklist lock (CR2, amended by CR5 — complete)**: two windows on `timer.status`, both pure predicates in `store/blocklist-lock.ts`. **Adding** (`addSite`, `PRESET_TOGGLE` with `applied: true`) is allowed in `idle`/`running`/`paused` (`isBlocklistAddAllowed`); **everything else** (`removeSite`, preset off, save/rename/delete preset) is `idle`-only (`isBlocklistEditable`); `completed` allows nothing until Reset. Enforced in the store actions (CR2.T1/CR5.T1, an `adds` flag in `applyBlocklistMutation`), the background handler `createMutationHandler` (CR2.T2/CR5.T2: `isAddDirectionMutation` reads the raw `applied === true`, so a forged target cannot widen the window; rejections log `{ type }` only) and the UI (CR2.T3/CR5.T3: `SiteList` form on `selectBlocklistAddAllowed`, × buttons, applied-preset toggles and the save/edit controls on `selectBlocklistEditable`; notice `blocklist.addOnly` while running/paused, `blocklist.locked` once completed). **Never enforce the lock in the UI alone**; the pure helpers stay status-agnostic. A site added while `running` is charged as distraction only from the add: `entrypoints/background.ts` credits the elapsed stretch (`growthTick.account()`) before and re-reads the open tabs after it. Since UI.T1 the popup renders one list (`SiteList` with `PresetPicker` in its `quickAdd` slot). UI.T7 is done: overlay buttons `Open anyway`/`Back to work`; `ScoreBadge` shows a neutral `Starting` until `isScoreTierSettled` (`lib/score/score-reveal.ts`, 10% built) unless `completed`; `CityEmptyHint` on the City tab. UI.T6 is done: `SiteList` hardening — `classifyEntryError` (`lib/blocking/entry-error.ts`) for specific error copy, `diffDomains` (`lib/blocking/diff-domains.ts`) drives row highlight/scroll and a live region (`use-list-changes.ts`), info feedback fades (`use-expiring-state.ts`). UI.T9 is done: `components/timer/DurationDrum.tsx` replaces `DurationPicker` (removed) and is the clock in a session; pure math `lib/timer/duration-drum.ts`, input hooks `use-drum-gesture`/`use-drum-wheel`, settle-time request `use-drum-commit` (one `requestSetDuration` per gesture, never per row). UI.T5 is done: shared popup controls live in `entrypoints/popup/App.css` (`:where(.popup) button` outline pill, one phosphor focus ring, placeholder `#8a948e`), guarded by `tests/unit/styles/popup-styles.test.ts`; the duration picker and numeral stay for UI.T9. UI.T4 is done (reworked by UI.T10: the add-only note shows only while running/paused, the summary is a 24px-min outline pill, `Resume`/`Paused` marker while paused, the list heading reuses `tabs.blocklist`): `BlocklistSummary` (opens the Blocklist tab: `Blocks N sites` / `No sites blocked`) sits under Start, and the notice copy is shorter and monospace. CR4 (presets as toggles, saved presets replace tags) is complete: `BlocklistEntry {domain, manual, presetIds}`, `BlocklistState {blocklist, appliedPresetIds, userPresets}` (persist v3, `migratePersistedBlocklist`), actions `togglePreset/savePreset/renamePreset/deletePreset`, messages `PRESET_*`, `isWellFormedBlocklistMutation` (`lib/messaging/blocklist-payload.ts`) for the payload shape, `validatePresetName` as the single name rule; details in `docs/features-analysis/saved-presets.md`. CR5 is complete. **Startup invariant (PR #5 review, `docs/pr-review/pr-5-review.md`, closed)**: background mutations wait for the startup reconciliation (the `ready` of `startBackground`) through `lib/messaging/startup-gate.ts`, created open only for a store that is already hydrated; never gate on `persist.hasHydrated()` after startup, since sync rehydrations reset it. The gate also covers the CR5 `addsSites` pre-step. The blocklist family is `BLOCKLIST_MUTATION_TYPES` with `isBlocklistMutation` (`lib/messaging/messages.types.ts`), and the mutation handler's switch ends with a `never` check. The component lock tests spy on `fakeBrowser.runtime.sendMessage` and assert no message is sent.
- **Score and population (CR3)**: both derive from `score.builtCharacters / TOTAL_CHARACTERS_PER_SESSION` — nothing is hard-coded to 600. Characters are counted from the session duration (`calculateBuiltCharacters(focusedMs, distractedMs, durationMs, total)`), never from the rounded `tickMs`, so 100% is always reachable. One table, `COMPLETION_BANDS` (`lib/score/completion-bands.ts`), drives the level (`bad` <30%, `good` ≥30%, `great` ≥70%, `excellent` at 100%) and the marginal population rate (5/10/20 per character); at 100% a bonus of 7% of the population reached is added (7383 today). `score` stores only `builtCharacters` as truth (`setBuiltCharacters` derives `population` and `level`); the persist `merge` rebuilds `score` from it. `distractionRatio` and `setPopulation` no longer exist.

- **CR6 complete (T1–T13, 2026-11-11/12): seeded 3D city.** Reference description: `docs/features-analysis/city-3d.md` §1 (as-built notes §7, measured budgets §8). A *city plan* (`generateCityPlan(seed)` in `lib/city/plan/`: roads, 30–48 lots on a 12×10 ground, 6 archetypes, 1–3 named landmarks, floors in build order, props, 200–300 floors, one of 6 palettes + ±25° hue shift; environment colors fixed, contrast ≥ 4.5:1) is derived from the session id (`seedFromSession`); visible floors come from `score.builtCharacters` (`visibleFloors`, damaged top floor only after a loss). Persist v4: `city` is only `{ sessionId }`; `CitySlice = { city, resetCityForNewSession }`, no dependencies. Malus is inside `builtCharacters` (`lib/score/malus-escalation.ts`), so score and city lose the same amount; the background advances progress only. Rendering: three.js lazy chunk (`CityView3D`, 146 KB gz) in the City tab via `CityPanel` (stage, HUD, hidden `role=status` summary at 10% milestones), renderer shell `components/city/three/` (scheduler, camera, meshes, ambient layer, floor animations, labels, bloom + CRT, `captureFrame`), text fallback `renderSkyline` when WebGL2 is missing/lost, full-city page `entrypoints/city/` (free camera, read-only), export via 3D capture or text city. Tests: pure logic in unit tests, three.js mocked; e2e `tests/e2e/city-3d.spec.ts` on the built extension (`?debug=render` hooks; found and fixed a `disposeScene` crash when leaving the City tab). Measured: 11 draw calls, ~1 ms/render, ambient ≤ 30 fps; **first City frame ~490–740 ms vs the 200 ms budget: open (changelog Open issues #22)**. Gotchas: `bunx wxt prepare` after editing locales (i18n key types); `bun run build` before `bun run e2e`; a background tab is never hidden on a display without a window manager.
