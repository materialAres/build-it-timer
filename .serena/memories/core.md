# build-it-timer — core

WXT MV3 browser extension ("Build-it! Timer Focus"): a focus-session timer that grows an ASCII city, blocks distracting domains during a session, and scores the session. Single TypeScript package — no separate deployable modules.

## Source map
- `entrypoints/` — `background.ts` (orchestrator), `blocked-overlay.content.tsx` (Shadow-DOM overlay), `popup/` (React UI).
- `store/` — Zustand store composed of `*.slice.ts` factories, `storage-adapter.ts` (persist adapter + self-write tracking), `sync-storage.ts` (`attachStoreSync`).
- `lib/` — pure domain logic (`url/`, `blocking/`, `timer/`, `city/`, `score/`, `messaging/`); only `lib/timer/alarm-adapter.ts` touches `browser.alarms`.
- `components/` — presentational React (`timer/`, `city/`, `blocklist/`, `score/`, `common/`).
- `utils/` — logger, duration formatting, hash, `Result`.
- `tests/` — unit · integration · e2e · helpers; unit tests mirror the source tree.
- `docs/` — `roadmap-en.md` (authoritative task cards), `changelog.md` (mandatory per-task record), `store-analysis.md`, `issue/`, `ui/ui-review-tasks.md` (UI.T* cards from the Impeccable critique; logic parts delegate to roadmap CRs).
- `PRODUCT.md` (product truth, neutral/minimal voice) + `DESIGN.md` / `.impeccable/design.json` (visual system "The Phosphor Skyline": phosphor green `#7dfba0` sole UI accent, mono everywhere, glow only on active/earned/alarming text) — design authority for any UI work; critique snapshots in `.impeccable/critique/`.
- `locales/en.yml` (default) + `locales/it.yml`.
- `CLAUDE.md` — binding design/testing rules (loaded every session). On demand: `docs/project-structure.md`, `docs/testing-matrix.md`; changelog procedure lives in the `changelog` skill (`.claude/skills/changelog/`).

## Invariants
- **Three worlds, typed messages only**: background / content script / popup never import each other's modules; they exchange `RuntimeMessage` variants (`lib/messaging/messages.types.ts`) via `sendMessage`/`onMessage` (`lib/messaging/bus.ts`).
- **Single writer = background.** The popup builds its store with `createAppStore({ readOnly: true })`; components call `request*` actions that send a `MutationMessage`, applied by `lib/messaging/apply-mutation.ts`. The popup converges through `attachStoreSync` (`storage.onChanged` → `persist.rehydrate()`; self-writes skipped via `SELF_WRITE`).
- **Pure core**: `lib/` functions receive clock/RNG/seed as parameters — no internal `Date.now()`/`Math.random()`. Collaborators are injected through slice factories (`StoreDependencies`) and ports (`AlarmProvider`, growth/rule appliers).
- **One city per session**, reset on the idle→running transition only; pause/resume keeps the built city.
- **Growth derives from cumulative `timer.focusedMs`** with the persisted wall-clock checkpoint `timer.lastAccountedAt` (not sampled ticks), so catch-up after popup close / worker restart is idempotent. Malus converts `distractedMs` at the same session cadence.
- **DNR**: blocklist → dynamic rules installed only while `status === 'running'`; there is a single blocklist (the allowlist was removed by CR1). The empty but enabled static ruleset (`public/rules/empty-rule-set.json`) must stay declared — Firefox ≤132 drops dynamic rules on restart without it.
- **Distraction tracking**: `TabDistractionTracker` seeds open tabs once and otherwise follows `tabs.onUpdated`/`onRemoved`, so it must be `refresh()`ed when the timer enters `running` — the construction-time seed runs while the store is idle, and a tab already open on a blocked site never emits an update. Malus accrual starts at the overlay's "Yes" (pre-`proceed` time is forgiven).
- **Persist**: key `timer-focus-store`, `version: 3` (CR4.T3), payload `{ timer, city, blocklist: { blocklist, appliedPresetIds, userPresets }, score, sessionHistory }`; `partialize` excludes `ui`; keep the slice-aware `merge` so fields added later rehydrate to their default instead of `undefined`.
- **Both build targets are MV3**; Firefox gets a `background.scripts` event page instead of a service worker. Permissions are declared manually in `wxt.config.ts` (WXT does not infer them).
- **Blocklist (single list, CR1 complete)**: the allowlist was removed end-to-end — popup UI/locales (CR1.T1), mutation protocol (CR1.T2), persisted data migrated to `{ blocklist, customTags }` at version 2 (CR1.T3), enforcement (`buildDnrRules(blocklist)`, `isDomainBlocked({ blocklist })`, CR1.T4), production state model (CR1.T5a) and tests (CR1.T5b/T5c). `BlocklistState` is `{ blocklist, appliedPresetIds, userPresets }` since CR4 (was `{ blocklist, customTags }`); helpers/actions take no list name. **Never reintroduce a second list or a precedence rule.** The only runtime reader of the legacy field is `lib/blocking/legacy-blocklist.ts` (`migrateBlocklistState`); raw version-1 JSON fixtures remain only in the `legacy-blocklist`, `store-snapshot`, `blocked-overlay`, `store` and `dnr-rules` tests.
- **Blocklist lock (CR2, amended by CR5 — complete)**: two windows on `timer.status`, both pure predicates in `store/blocklist-lock.ts`. **Adding** (`addSite`, `PRESET_TOGGLE` with `applied: true`) is allowed in `idle`/`running`/`paused` (`isBlocklistAddAllowed`); **everything else** (`removeSite`, preset off, save/rename/delete preset) is `idle`-only (`isBlocklistEditable`); `completed` allows nothing until Reset. Enforced in the store actions (CR2.T1/CR5.T1, an `adds` flag in `applyBlocklistMutation`), the background handler `createMutationHandler` (CR2.T2/CR5.T2: `isAddDirectionMutation` reads the raw `applied === true`, so a forged target cannot widen the window; rejections log `{ type }` only) and the UI (CR2.T3/CR5.T3: `SiteList` form on `selectBlocklistAddAllowed`, × buttons, applied-preset toggles and the save/edit controls on `selectBlocklistEditable`; notice `blocklist.addOnly` while running/paused, `blocklist.locked` once completed). **Never enforce the lock in the UI alone**; the pure helpers stay status-agnostic. A site added while `running` is charged as distraction only from the add: `entrypoints/background.ts` credits the elapsed stretch (`growthTick.account()`) before and re-reads the open tabs after it. Since UI.T1 the popup renders one list (`SiteList` with `PresetPicker` in its `quickAdd` slot). UI.T7 is done: overlay buttons `Open anyway`/`Back to work`; `ScoreBadge` shows a neutral `Starting` until `isScoreTierSettled` (`lib/score/score-reveal.ts`, 10% built) unless `completed`; `CityEmptyHint` on the City tab. UI.T6 is done: `SiteList` hardening — `classifyEntryError` (`lib/blocking/entry-error.ts`) for specific error copy, `diffDomains` (`lib/blocking/diff-domains.ts`) drives row highlight/scroll and a live region (`use-list-changes.ts`), info feedback fades (`use-expiring-state.ts`). UI.T9 is done: `components/timer/DurationDrum.tsx` replaces `DurationPicker` (removed) and is the clock in a session; pure math `lib/timer/duration-drum.ts`, input hooks `use-drum-gesture`/`use-drum-wheel`, settle-time request `use-drum-commit` (one `requestSetDuration` per gesture, never per row). UI.T5 is done: shared popup controls live in `entrypoints/popup/App.css` (`:where(.popup) button` outline pill, one phosphor focus ring, placeholder `#8a948e`), guarded by `tests/unit/styles/popup-styles.test.ts`; the duration picker and numeral stay for UI.T9. UI.T4 is done (reworked by UI.T10: the add-only note shows only while running/paused, the summary is a 24px-min outline pill, `Resume`/`Paused` marker while paused, the list heading reuses `tabs.blocklist`): `BlocklistSummary` (opens the Blocklist tab: `Blocks N sites` / `No sites blocked`) sits under Start, and the notice copy is shorter and monospace. CR4 (presets as toggles, saved presets replace tags) is complete: `BlocklistEntry {domain, manual, presetIds}`, `BlocklistState {blocklist, appliedPresetIds, userPresets}` (persist v3, `migratePersistedBlocklist`), actions `togglePreset/savePreset/renamePreset/deletePreset`, messages `PRESET_*`, `isWellFormedBlocklistMutation` (`lib/messaging/blocklist-payload.ts`) for the payload shape, `validatePresetName` as the single name rule; details in `docs/features-analysis/saved-presets.md`. CR5 is complete.
- **Score and population (CR3)**: both derive from `score.builtCharacters / TOTAL_CHARACTERS_PER_SESSION` — nothing is hard-coded to 600. Characters are counted from the session duration (`calculateBuiltCharacters(focusedMs, distractedMs, durationMs, total)`), never from the rounded `tickMs`, so 100% is always reachable. One table, `COMPLETION_BANDS` (`lib/score/completion-bands.ts`), drives the level (`bad` <30%, `good` ≥30%, `great` ≥70%, `excellent` at 100%) and the marginal population rate (5/10/20 per character); at 100% a bonus of 7% of the population reached is added (7383 today). `score` stores only `builtCharacters` as truth (`setBuiltCharacters` derives `population` and `level`); the persist `merge` rebuilds `score` from it. `distractionRatio` and `setPopulation` no longer exist.

- **CR6 in progress: CR6.T1 analysis done (`docs/features-analysis/city-3d.md`, decisions for T2a–T13) CR6.T2a, T2b, T3 and T4 done (T4: `visibleFloors`/`calculateLostCharacters`, `createScenePlan`/`createSceneFrame`, `summarizePlan`; top floor damaged only after a loss) (`lib/city/plan/`: `generateCityPlan(seed, options?)` returns a `CityPlan` — roads, 30–48 lots on a 12×10 ground, buildings from 6 archetypes, 1–3 named landmarks, floors in build order, props, total floors 200–300, one of 6 session palettes plus a ±25° hue shift; environment colors fixed, contrast ≥ 4.5:1 on the floor) (roadmap §2.9, 18 cards T1–T13 with T2/T5/T6/T8/T9 split a/b)**: replace the ASCII grid with a three.js city drawn from a seeded per-session plan (layout, archetypes, heights, palettes vary every session; same seed → same city); visible floors derived from `builtCharacters`, persist v4 drops `city.layers`/`city.buildings`; option A malus: the M4.T1 escalation moves into `builtCharacters` so score and city lose the same amount, a partly paid top floor shows as damaged. Perf rules: three.js lazy-loaded with the City tab only, render on demand, ambient ≤30 fps, instancing, ASCII fallback. Every CR6 card carries a **Docs** criterion (living docs updated per task, historical docs get a 'Superseded by CR6' banner). Analysis decisions: plan limits 12×10 ground / 120–180 floors; penalty = `malusForDistractionTicks(floor(distractedMs×total/durationMs))` over cumulative `distractedMs` (no proceed baseline, to confirm); partial top floor is damaged only after a loss.
